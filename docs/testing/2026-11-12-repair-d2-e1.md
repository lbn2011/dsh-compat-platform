## 1. D2 — what changed

`packages/repair/src/repair-plan.js` and `packages/repair/src/repair-preview.js` were
rewritten around a five-member, version-scoped vocabulary.

| Item | Before | After |
| --- | --- | --- |
| Plan version | `repair-plan/0.1-draft.1` | `repair-plan/0.2-draft.1` (0.1 still accepted with its old meaning) |
| Operations | 1 (`set-entry-flag`) | 5 (`set-entry-flag`, `set-entry-config`, `reorder`, `disable-conflicting`, `patch-insert`) |
| Postcondition | `documentSha256` + `entryIndex`/`field`/`value` | `documentSha256` only (coordinates retired with the single-edit model) |
| Tests | 42 | 68 (16 plan + 27 apply + 25 vocabulary) |

New refusal codes: `PLAN_OPERATION_NOOP`, `PLAN_CONFIG_KEY_INVALID`,
`PLAN_ENTRY_ID_INVALID`, `PLAN_CONFLICT_ID_INVALID`, `PLAN_CONFLICT_PROVENANCE_INVALID`.
New preview codes: `PREVIEW_ENTRY_CONFIG_ABSENT`, `PREVIEW_CONFIG_KEY_ABSENT`,
`PREVIEW_CONFIG_BLOCK_UNSUPPORTED`.

Two limitations were added rather than silently assumed away:
`PLAN_EDITS_ARE_LIMITED_TO_THE_ENTRY_LIST_SUBSET` (replacing the one-operation sentence)
and `CONFLICT_PROVENANCE_IS_CALLER_SUPPLIED_AND_UNVERIFIED`.

### 1.1 Why the version scopes the vocabulary

A `0.1` plan naming `patch-insert` is refused with `PLAN_OPERATION_UNSUPPORTED`. The
alternative — reading every plan with the newest rules — would silently change what an
existing `0.1` document means, and a repair plan is exactly the document where a silent
reinterpretation is worst.

## 3. E1 — verified green (one bounded round)

`packages/host` gained three modules and 28 package tests:

| File | Purpose |
| --- | --- |
| `src/page-snapshot.js` | pure `buildPageSnapshot(input)` + `createSlotCache()`; no DOM, no rendering |
| `src/frontend-log.js` | strict log-entry parser, 100-entry ring, hand-written RFC 6455 handshake and frame codec |
| `src/api.js` | mounts `GET /api/page-snapshot` and `/api/frontend-log` (fetch + upgrade) behind the carrier's admission |

`packages/host/src/index.js` calls `applyHostApi(ctx, …)` at the top of `apply()`, and
`packages/host/package.json` gained `./page-snapshot`, `./frontend-log` and `./api`.

**At the start of this task no bounded batch could run these tests.** The reasons were
structural, and they are recorded here because the fix changed the runner's control
closure:

- `scripts/bounded-runner/policy.sh:23-28` is an **exact-match** allow-list of unit
  bases. It contains no host prefix, and `diagnostics-gui-run` (the one host-adjacent
  slice) pins `EXPECT_SELECTED_TESTS=(tests/client.test.js tests/gui.test.js)`, a
  forbidden port and a live GUI, so it cannot carry API unit tests.
- `policy.sh` is one of the five modules hashed by `scripts/bounded-runner/core.manifest`.
  Adding a unit base is therefore not a local edit: it changes the control closure that
  every existing slice verifies, and re-qualification would follow. That is beyond a
  worker's authority, so it is reported to the captain rather than done.

### 3.1 What was verified instead, and how

These are **probes** (`node --input-type=module -e`), not a suite run, and they are
listed so the distinction cannot be lost:

- `acceptKey('dGhlIHNhbXBsZSBub25jZQ==')` returns `s3pPLMBiTxaQ9kYGzzhZRbK+xOo=`, the
  value printed in RFC 6455 §1.3.
- A real `node:net` server plus client: the upgrade reply is
  `HTTP/1.1 101 Switching Protocols` with a `Sec-WebSocket-Accept` computed from the
  client's own key; a masked text frame sent afterwards lands in the ring as
  `{"seq":1,"level":"uncaught","message":"socket boom","stack":"at handler","source":null,"at":null}`.
- A frame split across three writes is reassembled rather than refused; unmasked,
  fragmented, unknown-opcode and oversized-announced frames are each refused, the last
  before allocating.
- A strict context whose `ctx.get(name)` throws for unknown names still mounts all three
  routes and degrades per part
  (`SESSIONS_UNAVAILABLE,MESSAGES_UNAVAILABLE,PLUGINS_UNAVAILABLE`, `activeSession: null`).
- `applyHostApi` returns `null` and mounts nothing when the composition has no
  `connection` service; with one, both fetch routes and the upgrade register and dispose
  cleanly (`routes 2 → 0`).
- `buildPageSnapshot({})` reports four `*_UNAVAILABLE` codes rather than four empty
  lists; a provided-but-empty source reports `provided` with count 0.

Two product defects were found by these probes and fixed before any test was written:

1. The upgrade handler dropped the third `head` argument, so bytes the HTTP parser had
   already read past the request head were lost — a log line that arrived with the
   handshake would have vanished.
2. The collector and `createHostApi` read `ctx.connection`/`ctx.sessionQuery`/… as plain
   properties. An undeclared Cordis service is not a safe property read, so every access
   now goes through a guarded `resolveService()` that tries `ctx.get(name)` first.

### 3.2 What E1 must not be read as claiming

- No browser rendered anything and no DOM was read; the snapshot is host state.
- No real DSH carrier booted these routes; the admission fence is exercised through a
  double, and inheriting the carrier's trust policy is a design statement, not a measured
  one.
- The 100-entry ring, the 64 KiB frame ceiling and the field truncation limits are
  enforced in unit terms only.

## 4. What remains unestablished

- No real DSH carrier mounted these routes. The admission fence is exercised through a
  double; "the routes inherit the carrier's trust policy" is a design statement, and the
  round does not measure it.
- No browser sent a log line. The real-socket case proves the handshake and frame path
  against a `node:net` server in the same process, not against the product's carrier.
- The snapshot was never compared with a rendered page; it is host state by construction.
- `disable-conflicting` provenance is still caller-supplied (see §2.3).
