### 1.1 Defect 1 — a frozen object spread as if it were iterable

25 failures carried the same error, all from `src/pre-check.js:438`:

```
error: 'CONFLICT_LIMITATIONS is not iterable'
  buildSummary (src/pre-check.js:438:30)
  staticPreCheck (src/pre-check.js:360:14)
```

`CONFLICT_LIMITATIONS` is a frozen **object** (`{ HOST_VERSION_UNKNOWN: 'HOST_VERSION_UNKNOWN', … }`,
`src/conflict-detector.js:133`), but the summary built it with `[...CONFLICT_LIMITATIONS]`.
Every `staticPreCheck()` call therefore threw, which is why the whole pre-check test file
failed rather than one assertion.

The `5 !== 64` CLI failure was **the same defect, one frame out**, not a separate bug:
`preCheckFailure(PRE_CHECK_CODES.USAGE)` builds a summary before it can be printed, so the
usage path threw; the process entry point maps a rejected `main()` to
`PRE_CHECK_EXIT.INTERNAL` (5) by design:

```js
main(process.argv.slice(2)).then(
  (code) => { process.exitCode = code; },
  () => { process.exitCode = PRE_CHECK_EXIT.INTERNAL; },
);
```

Fix: `conflictLimitations: { ...CONFLICT_LIMITATIONS }` — matching both the declared type
(`Readonly<Record<string, ConflictLimitation>>`) and the assertion in
`tests/pre-check.test.js:107`.

### 1.2 Defect 2 — a backtick inside the CLI usage template literal

All five "the command line" subtests in `tests/profile-dump-layers.test.js` failed with a
`SyntaxError` raised while the spawned CLI was being compiled:

```
file:///…/src/profile-dump-cli.js:53
  --disclose-layers    Copy the export's `# == ` layer labels (usually file paths) into
                                          ^
SyntaxError: Invalid or unexpected token
```

The new `--disclose-layers` paragraph I added to `USAGE_TEXT` contained backticks inside the
template literal, which terminated the literal early. This is a real defect that the suite
caught and my own `node --check` did not: I checked `src/profile-dump.js` but not
`src/profile-dump-cli.js`.

Fix: the paragraph now quotes the marker with ordinary quotes (`"# == "`) and names
`layers[]` bare. `node --check src/profile-dump-cli.js` passes; the only backticks left in
the file are comments and the two template delimiters.

### 1.3 Defect 3 — a test whose premise was wrong

`tests/profile-dump-layers.test.js:283` ("provenance survives a refused document") asserted
`ok === false` for a document built from `- id: alpha` / `- not-a-row: 1`. That document is a
valid root sequence of two mappings, so `ok === true` is the correct answer and the assertion
was mine to lose. Fix: the fixture now uses a root mapping (`not-a-sequence: 1`), which is
genuinely refused (`inventory: 'none'`), and additionally asserts `layers[0].rowCount === 0`.

### 4.2 Root causes, one per code defect

**A. `predicted` was always empty (10 of the 14 failures).** `src/pre-check.js` asked
`conflict.owners.includes(owner)`. In `src/conflict-detector.js` every conflict is built with
`owners: [{ owner, uid }, …]` (e.g. `:783`, `:811`, `:825`, `:846`, `:888`, `:907`, `:922`), so a
string comparison could never match: every conflict landed in `preexisting` and every
"expected one prediction" assertion saw zero. Fixed to
`conflict.owners.some((entry) => entry.owner === owner)`.

**B. `manifestText` type was only checked when `manifest` was absent.** `staticPreCheck({
manifest, manifestText: 5 })` returned a summary instead of refusing the caller
(test 474, "Missing expected exception"). The type of an argument must not depend on which other
argument was passed; the check now runs unconditionally, before the `manifest === undefined`
branch.

**C. A malformed peer range was invisible whenever `engines.dsh` existed.** The peer block was an
`else if` of the `engines.dsh` branch, so `PEER_RANGE_NOT_STRING` was never reported for a manifest
that also declared `engines.dsh` (test 478). **Reading the manifest for shape** and **deciding
compatibility** are different jobs: the host ignores peers for *comparison* when `engines.dsh`
exists (`dsh-app-boot/lib/index.js:1097`), but a non-string peer range is still a malformed
manifest. The loop now always reports shape findings and only skips *comparison* when
`enginesHasDsh` is true.

**D. The row expectation in the profile-dump test was mine to fix, not the product's.** Test 518's
leaf asserted `layer: null` for a dump whose first line is `# == @fixture/dsh-bundle-probe`; a row
after a separator belongs to that separator's layer, i.e. `1`. My D1 edit had propagated the wrong
value into `tests/profile-dump.test.js:838`; corrected to `layer: 1`.

**E. `KEY_GRAMMAR` rejected npm scope form, which made C7 unreachable.** `src/conflict-detector.js:155`
was `/^[A-Za-z0-9][A-Za-z0-9._:@/-]*$/`. A host service key is a package name —
`tests/pre-check.test.js:343` expects `predicted[0].key === '@deepseek-ai/dsh-tools'` with code `C7`
— so the leading `@` made every DSH peer requirement both a bogus C9 and a C7 that could never
fire. Widened to `/^@?[A-Za-z0-9][A-Za-z0-9._:@/-]*$/`; reserved-prefix handling is unchanged, so
`@deepseek-ai/secret` and `dsh.internal` still produce C9 (with the reserved-prefix reason rather
than the grammar reason), and `node:fs` still produces C9.

### 4.3 Two findings that the failing tests did not name

**F. `totals.claimsAccepted` counted only the candidate's claims.** Test 490 expects `2` (the
candidate plus one declared resource) and test 499 expects `3` (one candidate plus two declaration
files). The counter now sums what *this run* contributed — the manifest's claims and each
declaration's — and deliberately excludes pre-existing occupancy, which is the table that was
already there rather than something this run asserts.

**G. An entry with an unreadable `platform` still produced a claim.** Test 478 expects
`claimsAccepted === 2` (`good`, `listy`), not 3: `platy: { platform: 9 }` must not be compared,
because a platform that cannot be read is not a constraint that can be checked. The claim is now
withheld for that entry. This is deliberately *not* symmetric with `inject`: a malformed `inject`
withholds only the requirement (the row occupancy is still real), while a malformed `platform`
withholds the claim (its compatibility cannot be stated).
