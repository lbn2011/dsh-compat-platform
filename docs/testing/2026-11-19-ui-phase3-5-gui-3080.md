## HTTP 验证尝试与失败原因

### 尝试 1：直接 curl（失败）
```bash
curl http://127.0.0.1:3080/api/conflict-report
# 返回：401 Unauthorized
```
**原因**：未携带浏览器会话 cookie（`dsh_session`），被 DSH 信任栅栏拦截。

### 尝试 2：Headless Chrome + URL token（失败）
- 脚本：`scripts/verify-3080-apis.mjs`（已删除）
- 方法：从 /var/log/dsh-web.log 提取初始 token（`?token=oC_c9Cj7sSPf7u2xqh4O5Jb-2oY6YHy8jAqYOQlSw4c`），用 chrome-driver 打开页面
- 结果：页面加载成功（200），但后续 fetch('/api/conflict-report') 返回 401
- 原因：Headless Chrome 未保存 session cookie，URL token 仅在首次加载时建立会话，后续 fetch 无凭据

### 尝试 3：Node.js fetch + Cookie 注入（失败）
- 脚本：`scripts/verify-3080-http.mjs`（已删除）
- 方法：在 fetch 请求头中注入 `cookie: dsh_session=<token>`
- 结果：401 Unauthorized
- 原因：Cookie 格式或 token 值不正确（URL token 与 session cookie 的对应关系未知）

### 结论
3080 的 `/api` 路由受 DSH 信任栅栏保护（loopback + trusted-host 检查 + 浏览器会话认证），自动化客户端无法在不修改 DSH 源码或绕过安全机制的情况下获取有效会话。这是设计的安全特性，不是测试障碍。
